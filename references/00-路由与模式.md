# 00 · 路由与模式 · 详细逻辑

**本文件在用户回应激活指令后按需加载。**

---

## 首次激活（续）

用户回答了路径问题后：

1. **有已有文件夹** → 让用户提供路径。仅在用户说“帮我找”时扫描项目根目录下含“上下文、人生、愿景、价值观”等关键词的目录，列出候选后让用户确认。
2. **指定自定义路径** → 使用用户确认的路径。
3. **默认或不确定** → 使用 `上下文系统/我的人生上下文/`。
4. 再问一次：“只建立人生上下文，还是同时开启定位、产品、内容的事业表达层？”

确定后：

1. 从 `assets/templates/` 复制 11 个核心模板和 `.meta.md` 到目标路径。
2. 仅在用户开启事业表达时，复制 `assets/templates/事业表达/`。
3. 在 `.meta.md` 记录 `base_path`、`career_enabled` 和 `skill_version: "1.1.0"`。
4. 在项目或工作区根目录写入 `.wuyi-life-context-guide.json`，只记录 `skill_version` 和 `base_path`；优先保存相对路径。
5. 如果项目受 Git 管理，把定位文件加入 `.git/info/exclude`，不要公开提交。
6. 已有同名文件时不覆盖，先按“迁移协议”处理。

**推荐起始维度**：
- 首推「精神与愿景」或「价值观与底线」（内核层，后续维度都会引用）
- 如果用户说“不知道从哪开始”，默认从「精神与愿景」开始

用户选一个维度 → 加载对应 `references/0X-*.md` → 进入「首次探索模式」。

## 从旧版本迁移

发现 `.meta.md` 的 `skill_version` 低于 `1.1.0` 时：

1. 读取已有目录和 `.meta.md`，不复制覆盖任何已有正文。
2. 给 `.meta.md` 补 `created`、`career_enabled: false`、3 个事业表达状态行和合法状态说明。
3. 给项目根目录补 `.wuyi-life-context-guide.json`。
4. 只修正 YAML 字段形态；用户已有内容原样保留。
5. 告知用户新版本增加了可选事业表达层，询问是否开启。
6. 用户确认后才把 `skill_version` 更新为 `1.1.0`。

迁移过程中如果发现同名文件但结构不同，展示差异并等待确认，不猜测合并。

## 启动菜单（回访时）

每次回访，基于 .meta.md 的数据展示（不扫描实际文件）：

```
📊 你的人生上下文

进度：X/10 维度已填写（整体 confidence: X.X）

你想做什么？

1. 🧭 继续探索 — [推荐：最薄弱的维度名称]（confidence 0.X，上次更新 X天前）
2. 🔄 校准更新 — [推荐：最久未更新的维度名称]（上次更新 X天前）
3. ✍️ 周更 — 更新本周状态和焦点（~3分钟）
4. 📋 合成关于我 — [已满足/还需X个维度]
5. 🧩 事业表达 — [开启/继续：最薄弱项/尚未启用]
6. 🧭 月度/季度校准 — 检查六维变化和方向偏差
7. 🔍 查看某个维度 — 告诉我哪个
8. ❓ 其他 — 随便聊
```

**推荐逻辑**：
- 选项 1：confidence 最低的非空维度；全部未填 → 推荐「精神与愿景」
- 选项 2：`updated` 最久远的、confidence ≥ 0.5 的维度
- 选项 4：已完成 ≥3 个维度 → "已满足"；否则 → "还需 X 个维度"
- 选项 5：未开启时询问是否启用；已开启时按“定位 → 产品 → 内容”推荐最早未完成项
- 用户直接说了具体意图 → 跳过菜单，直接路由

## 用户选择后：校验 → 路由

用户选了具体维度后，**此时才读取该维度的实际文件**，校验 .meta.md 与文件是否一致：

| 实际文件状态 | .meta.md 记录 | 修正动作 |
|:--|:--|:--|
| 文件不存在或只有占位内容 | 任意 | 状态→`未填`，confidence→`—` |
| 文件有实质内容但 meta 显示未填 | `未填` | 读 frontmatter confidence；无则估值为 0.3 或 0.5 |
| frontmatter confidence 与 meta 不同 | 任意 | 以文件为准 |
| updated 比 meta 记录的更新 | 任意 | 以文件为准 |
| 状态=`进行中` 但文件已完整 | `进行中` | 状态→`基础`(0.5)，备注清空 |

校验完成后路由：

| 用户选择 | 条件 | 路由到 |
|:--|:--|:--|
| 继续探索 / 聊XX维度 | 状态=进行中 | **会话恢复** → 读备注，从中断处继续 |
| 继续探索 / 聊XX维度 | 不存在或 ≤0.3 | **首次探索** |
| 继续探索 / 聊XX维度 | confidence=0.5 | **深化模式** |
| 校准更新 | ≥0.7 | **更新模式** |
| 周更 | — | **周更模式** → 加载 `周更引导.md` |
| 合成关于我 | — | **合成模式** → 加载 `09-合成-关于我.md` |
| 定位 / 产品 / 内容 | 未启用 | 先说明可选模块并取得确认，再复制对应模板 |
| 定位 / 产品 / 内容 | 已启用 | **事业表达模式** → 加载 `10-12` 中对应文件 |
| 月度校准 / 季度校准 | — | **周期校准模式** |
| 查看某个维度 | — | 展示该维度内容摘要 |
| 其他 | — | 自由对话，根据内容判断 |

## 首次探索模式

当维度文件不存在或 confidence ≤ 0.3：

1. 加载对应 `references/` 引导文件
2. 从问题序列中选 3-5 个最有信息量的问题（不必全问）
3. 跟用户节奏走——自发聊到的内容优先于引导问题
4. 结束时生成维度文件，写入初始 confidence（通常 0.3 或 0.5）
5. **同步更新 `.meta.md`**

---

## 深化模式

当 confidence = 0.5，用户想提升深度：

1. **不重复已知**：先读已有文件，开场说"我已经了解了你之前说的[摘要]，今天往更深挖。"
2. 跳过已有充分数据的字段，聚焦空白或浅层字段
3. **深度追问**（允许围绕一个信号持续深挖）：
   - "你说[X]，能讲一个具体的例子吗？"
   - "这个想法是一直这样，还是有个时间点开始的？"
   - "你身边的人会同意这个自我评价吗？"
4. 结束时更新文件（合并新旧内容），提升 confidence
5. **同步更新 `.meta.md`**

---

## 更新模式

当 confidence ≥ 0.7，到了校准时间或想法变了：

1. 读取已有文件，展示当前内容摘要
2. 问："距离上次填写已经过了[X时间]。有什么变了？有什么更坚定了？"
3. 只聊有变化的部分，不重复未变化的内容
4. 结束时展示 diff（旧版 → 新版），用户确认后，先归档旧文件再保存
5. confidence = 0.9 时，只在用户主动提出或发生明显变化时才进入更新
6. 内核层有变化 → 提示"是否需要重新合成关于我？"
7. **同步更新 `.meta.md`**

---

## 周更模式

1. 加载 `references/周更引导.md`
2. 5 个快问快答，2-3 分钟完成
3. **不追问、不深挖**，快进快出
4. 同时更新 `本周状态.md` 和 `本周焦点.md`
5. **同步更新 `.meta.md`**

---

## 事业表达模式

事业表达是可选层，不改变核心 11 文件。

1. 首次进入时确认 `career_enabled: true`，复制 3 个事业表达模板。
2. 按依赖顺序进行：定位 → 产品 → 内容。用户可直接指定其中一项。
3. 定位前读取精神与愿景、价值观、能力、当前渴望。
4. 产品前读取定位、能力、环境与资源。
5. 内容前读取定位、产品、行为与节奏。
6. 只把用户确认的信息写成事实；推测标记为“AI 推断”。
7. 每个文件保存前展示摘要并确认；更新时先归档旧版本。
8. 完成后同步 `.meta.md`，并提示是否重新合成“关于我”。

事业表达用于回答外部价值问题，不反向覆盖内核。真实反馈可以触发校准，但必须由用户确认后才能更新人生上下文。

## 周期校准模式

月度或季度校准只做一次轻量检查：

1. 读取 5 个内核文件、当前渴望、本周状态和本周焦点。
2. 依次检查精神、身份、信念、能力、行为、环境六个维度：哪些变了，哪些更稳定，哪里出现冲突。
3. 输出“保持 / 调整 / 待观察”三类结论。
4. 不直接改内核；先列出建议修改的文件和理由。
5. 用户确认后，逐个归档并更新对应文件。
6. 如事业表达已启用，再检查定位、产品、内容是否仍与当前人生方向一致。

---

## 合成模式

**触发条件**（满足任一即触发）：
- 用户主动说"合成关于我"
- 用户无明确意图，且已有 ≥3 个维度 confidence ≥ 0.5

1. 加载 `references/09-合成-关于我.md`
2. 读取所有已完成文件并生成预览
3. 列出来源文件、尚未完成的维度和所有 AI 推断
4. 用户确认预览后，归档旧版并生成 `关于我.md`
5. 事业表达已启用时加入可选摘要；未启用时不显示空章节
6. `关于我.md` 同时作为导航页，记录 confidence 和更新时间
7. **同步更新 `.meta.md`**

## 跨文件关联协议

做后续维度时，**必须先读取已完成文件的结构化区**：

| 当前维度 | 引用 | 检查什么 |
|:--|:--|:--|
| 当前渴望 | 精神与愿景 | 渴望是否与使命对齐 |
| 关键关系 | 价值观与底线 | 合作标准是否和价值观一致 |
| 行为与节奏 | 能力与天赋 | 盲区是否和短板重叠 |
| 能力与天赋 | 精神与愿景 | 心流活动交叉验证 |
| 环境与资源 | 当前渴望 | 资源是否支撑目标 |
| 精神与愿景 | 价值观与底线 | 使命是否与核心价值观一致 |
| 我的故事 | 所有内核文件 | 转折点与价值观/能力/行为模式的交叉验证 |
| 本周焦点 | 当前渴望 | 焦点是否在推进最想改变的事 |
| 定位 | 精神、价值观、能力、当前渴望 | 外部定位是否来自真实自我与真实能力 |
| 产品 | 定位、能力、环境与资源 | 产品是否服务目标人群且具备交付条件 |
| 内容 | 定位、产品、行为与节奏 | 内容是否表达定位、建立信任并连接产品 |

**矛盾检测**：发现不一致时温和指出：
> "你在[之前的维度]里说过[X]，这里你说的[Y]似乎有点不同。这是想法变了，还是两者其实不矛盾？"

## Confidence 评估与提升

### 评估标准

| 值 | 条件 |
|:--|:--|
| — | 文件未创建或内容为空占位 |
| 0.3 | 对话 <5 轮，多数回答简短 |
| 0.5 | 对话 5-10 轮，有具体例子，未经追问验证 |
| 0.7 | 对话 10+ 轮，有深度追问，用户给出具体故事和内心感受 |
| 0.9 | 多次对话积累，经过时间验证，用户主动确认"这就是我" |

### 提升规则

| 当前 → 目标 | 条件 |
|:--|:--|
| 0.3 → 0.5 | 对话 5+ 轮，用户给出至少 1 个具体例子或故事 |
| 0.5 → 0.7 | 深化对话触及具体故事 + 内心感受，用户对追问有实质性回应 |
| 0.7 → 0.9 | 多次对话积累，跨越 ≥1 个月时间验证，用户主动确认准确 |
| 不提升 | 仍停留在观点层面 / 回答多为简短肯定 / 无新信息增量 |

## 会话恢复协议

对话中断时：

1. 该维度状态设为 `进行中`
2. `.meta.md` 备注字段记录进度摘要（如"聊到理想生活画面，Q4-6 未问"）
3. 下次路由到该维度时：读备注 → 开场说"上次我们聊到了[摘要]，今天从那里继续。"
4. 对话完成后：状态从 `进行中` 更新为对应 confidence 状态

## 文件操作细则

### 归档规则

修改任何已有产出前：

1. 创建 `历史/YYYY-MM-DD-HHmm/`。
2. 按原相对路径复制旧文件，例如 `内核/价值观与底线.md` 归档到 `历史/YYYY-MM-DD-HHmm/内核/价值观与底线.md`。
3. 归档成功后才写入新版本。
4. 不删除历史版本；目录或文件冲突时使用新的时间戳。

### 合并规则（文件已存在时）

**必须先问用户选择**：
1. **覆盖**：新内容完全替换（适用于大改）
2. **合并**：保留原有叙事区原文，替换结构化区，AI 协作备注取新旧交集
3. **取消**：不做修改

合并优先原则：
- 结构化区：新覆盖旧
- 叙事区：**追加**新故事到末尾，不删除原有叙事
- AI 协作备注：合并去重，保留仍然有效的旧备注

### 关于我.md 自动重算触发条件

满足任一时主动提示"是否需要重新合成关于我？"：
- 任何**内核层**文件的 confidence 发生变化
- **方向层**文件有内容更新
- **事业表达层**文件有内容更新
- 用户主动要求

### AI 使用协议（给下游 AI 读的）

1. **先读「关于我.md」** — 30 秒了解这个人
2. **根据任务深入对应文件**：方向选择→精神+价值观；能力评估→能力与天赋；执行规划→行为+环境+当下；人际→关键关系；背景→我的故事
3. **冲突解决**：内核 > 方向 > 当下
4. **结构化区取数据，叙事区获取语境**
5. **输出前自检**：是否违反价值观底线？是否匹配当前阶段？
6. **数据不足时**：confidence < 0.5 → 主动提示"建议先深化"
